# OpenMirror

**Private conversations. Deeper understanding. Evidence behind every insight.**

OpenMirror turns a WhatsApp chat export into a chaptered, evidence-backed report, entirely on your own
computer. Every claim in the report opens a case file with the exact messages behind it (verbatim, with
the original timestamp and source line number), the method used, a confidence level with its reason, and
the counterexamples that argue against it.

* **Local-first.** The API binds to `127.0.0.1`, the browser is locked to that API by a Content-Security-Policy,
  there is no account, no telemetry and no AI provider. Nothing leaves your machine.
* **Correctness before AI.** Phase 1 is deterministic: a streaming parser with a full import audit, and
  statistics you can recompute by hand. No language model is involved.
* **Evidence before interpretation.** No interest scores, no "red flags", no guesses about motives.

> Status: **Phase 1 (WhatsApp Intelligence Engine)** is complete. See [docs/STATUS.md](docs/STATUS.md).

## Quick start

Requirements: Python ≥ 3.11, Node.js ≥ 20.

```bash
# 1. Backend (FastAPI on http://127.0.0.1:8000)
cd backend
python -m venv .venv
.venv/bin/pip install -e ".[dev]"          # Windows: .venv\Scripts\pip install -e ".[dev]"
.venv/bin/python -m openmirror              # run from the backend/ directory

# 2. Frontend (Next.js on http://127.0.0.1:3000), in a second terminal
cd frontend
npm install
npm run build && npx next start -H 127.0.0.1 -p 3000
# or, for development with hot reload:  npm run dev -- -H 127.0.0.1
```

Open <http://127.0.0.1:3000> and drop in an export.

**Try a fictional sample first.** [`samples/`](samples) has synthetic chats (Android `.txt`, iPhone `.zip`,
and a group chat). They were generated by `python -m openmirror.synthetic` and contain no real messages.

### Getting a WhatsApp export

* **Android:** open the chat → ⋮ → More → Export chat → *Without media* → save the `.txt`.
* **iPhone:** open the chat → contact name → Export Chat → *Without Media* → save the `.zip`.

Both files can be uploaded as is. ZIP media is never extracted or read.

## What the report contains

| # | Chapter | What it answers |
|---|---|---|
| 01 | The Overview | Span, volume, active days, the split between people, the busiest day |
| 02 | The People | Each person's message length, questions, media, emoji, daily rhythm, turn-taking |
| 03 | The Dynamics | Who starts sessions, how quickly people reply (with counterexamples) |
| 04 | The Timeline | Daily calendar, weekly rhythm, longest streak, longest silences |
| 05 | The Moments | Biggest conversations, months that surged or dropped, all on one axis |
| 06 | The Recurring Threads | Words that recur across sessions, and what marked each period |
| 07 | The Shifts | Early vs middle vs late: pace, initiation, reply speed, share |
| 08 | The Fine Print | Import audit, what the analysis cannot see, scope |

You can also search every message (SQLite FTS5), click any month or day to read it, change the
session-gap definition and recompute, and open the full import audit.

## Configuration

All settings are environment variables with private defaults:

| Variable | Default | Meaning |
|---|---|---|
| `OPENMIRROR_DATA_DIR` | `~/.openmirror` | Where the SQLite database lives (created with mode `0700`) |
| `OPENMIRROR_HOST` | `127.0.0.1` | Bind address. A non-loopback value prints a warning |
| `OPENMIRROR_PORT` | `8000` | API port |
| `OPENMIRROR_MAX_UPLOAD_MB` | `200` | Upload limit (enforced while streaming) |
| `OPENMIRROR_MAX_CHAT_TEXT_MB` | `500` | Limit on the decompressed chat text |
| `OPENMIRROR_MAX_ZIP_ENTRIES` | `20000` | ZIP entry limit |
| `OPENMIRROR_CORS_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | Allowed browser origins |
| `NEXT_PUBLIC_API_BASE` (frontend, build time) | `http://127.0.0.1:8000` | Where the UI finds the API |

## Privacy

* **Where data goes:** into one SQLite file in `OPENMIRROR_DATA_DIR`. Nowhere else.
* **Deleting:** the trash icon removes the conversation, its participants, messages, full-text index entries,
  import audit, analysis runs, findings and evidence references. SQLite `secure_delete` is on and the
  write-ahead log is truncated afterwards, so deleted rows aren't left behind in the file. Uploaded files are
  streamed to a temporary file that is deleted right after import. Failed imports keep nothing.
* **Logs** contain IDs and counts only, never message text. HTTP access logs are off because URLs can contain
  your search terms.
* **The other people in your chat** didn't choose to be analysed. Keep reports to yourself.
* **Never commit real exports.** `.gitignore` excludes databases and a `private/` folder. Tests use only
  synthetic data.

## Development

```bash
cd backend && .venv/bin/pytest            # 84 unit/integration tests
cd frontend && npm run lint && npm run test:e2e   # Playwright: upload → report → evidence → delete
```

The e2e suite starts its own backend on port 8100 with a temporary data directory and builds the frontend
into `.next-e2e`, so it never touches your data or your normal build.
